# CodeArena 26 demonstration

Start `npm run dev`. Open `/citizen/hazards`, `/admin/hazards`, `/ngo/hazards`, `/relief/hazards` and `/public-map`. Prepare different photos for the report, independent observation and clearance. Demo wards, roads, councils, shelters and weather readings are synthetic.

1. **Citizen report and geography:** select the original reporter, capture GPS or use the explicitly labeled demo location, choose a hazard, and add a title, description and photo. Request drinking water and shelter. Submit and inspect the saved case, automatic ward/road mapping and council ticket. The demo point `6.952, 79.88` belongs to Demo North Ward / Demo Council B. A point outside the synthetic coverage shows that limitation explicitly.
2. **Explain evidence and urgency:** inspect the five checks and server-extracted photo metadata. With Gemini configured, show image/location/risk outputs, structured urgency and the aggregate verdict. Without it, show unavailable checks and human review. Missing photo GPS is shown as missing; a conflicting embedded location cannot automatically confirm the report.
3. **Nearby confirmation:** in a second citizen tab select Nearby resident and share a current location within 200 m. In government, open the report, enter a reviewer note and request nearby confirmation. The invited resident supplies a different photo, observation and notes. The officer sees that independent evidence and a reevaluated cluster check. Use the demo location or browser GPS emulation for a local rehearsal; do not enter a real unsafe area for the demo.
4. **More-information loop:** request additional evidence from the original reporter, then upload another photo and notes. Show the saved history, urgency and council ticket remaining open through reevaluation.
5. **Confirmation and automatic routes:** filter the government queue by council/ward, select an urgency level and confirm with a reason. Its exclusion area appears on both the citizen and anonymous maps. Nearby citizen alerts include route guidance automatically. If the resident is inside the hazard buffer, the alert correctly says a screened route is unavailable. A configured OSRM provider can supply candidates for a resident outside exclusions; the entire route is screened.
6. **Relief coordination:** in `/relief/hazards`, find the help request and allocate the nearest eligible shelter with enough places. Inspect the shared capacity reduction and route result. A household inside a hazard needs crew-assisted extraction, so the allocation contains a reservation and explicit extraction guidance without invented geometry. Record the relief organization and supplies.
7. **Crew dispatch and closure:** government assigns the case to `demo-ngo`. The NGO queue shows its assigned case; submit a new clearance photo and notes. The council ticket resolves, the public map removes the hazard and citizens receive the closure update. The relief coordinator releases shelter places when occupants leave.
8. **Independent weather detection:** run `npm run weather:replay` or select the flood scenario in government monitoring. A simulated threshold creates a pending case and nearby warning with automatic guidance without a citizen complaint. Explain that this is an early warning awaiting verification.
9. **Reporting moderation:** create a separate test report, reject it with an officer's reason, and ban that reporter through the moderation panel. Show that another hazard submission is blocked, then lift the restriction with an appeal reason and show reporting restored. Keep the audit history visible.
10. **Public access and privacy:** open `/public-map` in a signed-out window. It shows generic active hazards, warnings and shelters without private report text, photos, resident locations or moderation records. Finally, stop location sharing in the nearby resident tab to remove its stored position and invitations.

If cloud services are configured, optionally show the existing resource inventory/SOS dashboards and government alert composer. Sending real SMS/email is a separate deliberate operation; the weather replay only changes the in-app demo state.

For an automated rehearsal, run `npm run test:e2e`. It drives the real report, community confirmation, moderation, urgency/council filters, automatic alert guidance, relief and clearance UI with an isolated store and fixture photos. `npm run verify:live` separately inventories configuration; follow [live validation](live-validation.md) to test configured external services.
